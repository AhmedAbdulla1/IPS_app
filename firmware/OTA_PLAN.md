# خطة تحديث الفيرموير عن بُعد (OTA) - مسودة أولية

**الحالة:** لسه مش متبنّاة - ده بس توثيق للنقاش والخطة المستقبلية.
راجع `MESH_DESIGN.md` و`MESH_PROGRESS.md` للسياق الكامل لباقي النظام.

---

## 1. الوضع الحالي

مكتبة `mesh_lite` فيها موديول OTA مدمج وشغال فعليًا (بيظهر في اللوج
عند الإقلاع):

```
[ESP_Mesh_Lite_OTA]: SHA-256 for current firmware: ...
```

بس **إحنا لسه معملناش أي كود بيشغّله فعليًا** - يعني مفيش مسار حالي
لتحديث فيرموير أي node لاسلكيًا.

---

## 2. المشكلة الجذرية: الـPartition Table الحالي مش بيدعم OTA

`partitions.csv` الحالي (في `IPS_Mesh_Root` و`IPS_Mesh_Node`) فيه
partition واحدة بس للتطبيق:

```
nvs,data,nvs,0x9000,24K,
phy_init,data,phy,0xf000,4K,
factory,app,factory,0x10000,2M,
```

الـOTA بيحتاج **partition-ين منفصلتين للتطبيق** (`ota_0` و`ota_1`) زائد
partition `otadata` لتتبّع أي واحدة فيهم شغالة دلوقتي - عشان الجهاز
يقدر يستقبل ويفلاش نسخة جديدة **وهو لسه شغال بالقديمة**، وبعدين يقفز
للجديدة بعد التأكد إنها سليمة (rollback ممكن لو فشلت).

**من غير التغيير ده، مفيش OTA ممكن يشتغل خالص - حتى لو باقي الكود
جاهز.**

---

## 3. مشكلة إضافية: الـRoot معزول عن الإنترنت عمدًا

تصميمنا الحالي (`MESH_DESIGN.md` §4.7) بيخلي الـRoot معزول تمامًا عن
الإنترنت لأسباب أمنية. مسار الـOTA "التقليدي" بتاع mesh_lite بيفترض
إن الـRoot عنده اتصال إنترنت يجيب منه الفيرموير الجديد (عادة عبر HTTP).

**البديل المطلوب:** الفيرموير الجديد يوصل للـRoot عبر **نفس كابل
الـSerial/USB** اللي متوصل بيه بالـPC في غرفة التحكم (نفس القناة
المستخدمة لبيانات الـHealth Monitoring)، وبعدين الـRoot يوزّعه داخل
شبكة الـmesh لباقي النودز.

---

## 4. الخطوات المطلوبة (لما نبدأ التنفيذ)

- [ ] إعادة تصميم `partitions.csv` بـ`ota_0`/`ota_1`/`otadata` في
      المشروعين (Root وNode) - محتاج حساب المساحة المتاحة بدقة على
      فلاش 4MB (كل صورة هتاخد مساحة أصغر من الـ2MB الحالية)
- [ ] بناء بروتوكول استقبال الفيرموير الجديد عبر الـSerial في الـRoot
      (شبيه ببروتوكول `HEALTH:` الموجود، بس لنقل بيانات ثنائية كبيرة)
- [ ] دمج استدعاء API الخاص بـ`ESP_Mesh_Lite_OTA` لتوزيع الفيرموير
      المُستقبل داخل شبكة الـmesh (تفاصيل الـAPI محتاجة مراجعة من
      `managed_components/espressif__mesh_lite/include/` وقت التنفيذ)
- [ ] تحديث `pc_health_service` (أو أداة منفصلة) عشان تقدر تبعت ملف
      `.bin` جديد للـRoot عبر نفس منفذ الـSerial
- [ ] اختبار ميداني على node واحد بعيد (3-4 hops) قبل الاعتماد على
      الطريقة دي لأي عدد أكبر من النودز - الـOTA فوق mesh متعدد القفزات
      أبطأ وأكتر عرضة للفشل من flash مباشر بالـUSB

---

## 5. البديل الحالي (لحد ما الـOTA يتبنى)

لأي تحديث مطلوب دلوقتي، الطريقة الوحيدة المتاحة: **رفع مباشر بالـUSB**
لكل node على حدة، باستخدام `firmware/tools/flash_all.py` (بيدعم رفع
متوازي لعدة بورتات مع بعض في نفس الوقت - عملي لعدد صغير من النودز على
المكتب، مش عملي لعدد كبير موزع في المبنى بعد التركيب).
